Software architecture

  • Persistence: SQLite repository in src/services/repository.py.
  • Solver: PuLP model in src/RunAuctionModule.py.
  • Auction orchestration: src/AuctionController.py and src/BiddingController.py.

Installing the necessary Python libraries

From the workspace root (ForeverFair2026), install all dependencies:

pip install -e ".[dev]"

This installs FastAPI, Uvicorn, Jinja2, PuLP, Pydantic, Python-multipart, pytest, and httpx from the project's pyproject.toml.

To start the development server after installation, run:

python -m uvicorn src.web.app:app --reload

Then visit http://127.0.0.1:8000/ in your browser.

Index decoding rules used by legacy code

Well token format: wellNNNN.

well_number = 1 + floor((index - 1) / number_pump_periods)
pump_period = 1 + (index - 1) mod number_pump_periods

Control-point token format in HEDCON: bonNNNN.

control_point = 1 + floor((index - 1) / number_control_periods)

Control-point token format in MPS rows: numeric row name.

control_point = 1 + floor((row_index - 1) / number_control_periods)
effect_period = 1 + (row_index - 1) mod number_control_periods

How to use an existing groundwater model

Run your model through GWM2K or similar to export a linear program, with decvar, hedcon, and mps files. This code here reads those files to get the response matrix, the number of wells, the number of control points, and the number of time periods. In principle, then, this code will work with any groundwater model that works with GWM2K. Typically, this is the responsibility of a competent hydrologist. 2. Import .decvar file

A GWM2K .decvar file defines decision variables (wellNNNN NC LAYER ROW COL FTYPE FSTAT stress_period). One well row is created per unique well number, with grid location stored from ROW and COL.

3. Import .hedcon file

A GWM2K .hedcon file lists head constraints (bonNNNN LAYER ROW COL SENSE RHS_head stress_period). Import creates one control-point row per unique control-point number and stores per-period bounds from RHS_head in default_control_point_bounds. These defaults are used by the optimizer whenever no auction-specific bounds have been applied via the Hydrologist maintenance page.

4. Import .mps file

A GWM2K .mps file contains the response matrix (COLUMNS section), head-constraint right-hand sides (RHS section), and well capacities (BOUNDS section). Import populates the response_factors table (auction-scoped) and default_control_point_bounds (RHS bounds, no auction, used as optimizer fallback). control_point_bounds is left empty; apply defaults for a specific auction from the Hydrologist maintenance page. Requires an existing manager-created auction for response factors. Default dimensions are from the Tianqiao example. Caution, import may be slow because these can be big files.

5. Import trader names

Upload a tab-delimited file with columns full_name, trader_first_name, and trader_last_name. A template file is at data/Tianqiao/Trader_names.csv.

The import derives trader_id, name, and trader_loginid from the last name. If the same last name appears more than once in the file, a numeric suffix is appended to each duplicate (e.g. Li, Li1, Li2).

6. Import trader-well assignments

Upload a tab-delimited file with columns name and well_id. A template file is at data/Tianqiao/Trader_wells.csv.

Requirements:

  • name must exactly match a value in the traders.name column (case-sensitive).
  • well_id must exactly match a value in the wells.well_id column.
  • A trader may have more than one well; each well can be assigned to only one trader.

The import updates wells.trader_id for each matched row. Rows that fail either check are skipped and listed in the notice.

7. Import well latitude and longitude

Upload a tab-delimited file with columns well_id, latitude, and longitude. Updates the wells table with spatial coordinates.

8. Import control point latitude and longitude

Upload a tab-delimited file with columns control_point_id, latitude, and longitude. Updates the control_points table with spatial coordinates.
