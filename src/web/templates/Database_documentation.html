Forever Fair Database Documentation

This page documents the SQLite schema used by Forever Fair. The schema is created in src/SetupForeverFairDB.py (SCHEMA_DDL), and most writes/reads are performed through src/services/repository.py and SetupForeverFairDB import helpers.

Initialization convention: Setup imports use auction_id = 0 for initial rows in both well_quota (initial quota via quota_auction_start) and control_point_events (initial head values: minimum_head from HEDCON, actual_start_head computed from HEDCON and MPS together). The optimization computes the LP right-hand side as minimum_head − actual_start_head at runtime.

Table: Catchment_info

meta_key (TEXT, PRIMARY KEY): Name of a global catchment setting. Used for keys such as inferred GWM dimensions, synthetic time, period length, and bidding-period count.

meta_value (TEXT, NOT NULL): Value for the setting key, stored as text and interpreted by caller logic.

Common keys: synthetic_current_date, num_bidding_periods, period_length_hours, mps_loaded_date, mps_notes, gwm_num_wells, gwm_num_pump_periods, gwm_num_control_points, gwm_num_control_periods.

Table: traders

trader_id (INTEGER, PRIMARY KEY AUTOINCREMENT): Internal numeric trader identifier used throughout joins and foreign keys.

name_tag (TEXT, NOT NULL): Trader display/name key used by UI and several import joins (for example trader-well assignment import). One trader can own more than one well.

trader_loginid (TEXT): Login identifier value imported with trader names. Currently derived from surname in importer.

trader_password (TEXT): Reserved legacy column for password storage; not used by current auth flow.

trader_first_name (TEXT): Trader first name imported from trader names file.

trader_last_name (TEXT): Trader last name imported from trader names file.

trader_address (TEXT): Reserved contact/location field.

trader_city (TEXT): Reserved contact/location field.

trader_phone (TEXT): Reserved contact field.

trader_email (TEXT): Reserved contact field.

Table: wells

well_id (INTEGER, PRIMARY KEY AUTOINCREMENT): Internal well identifier used by bids, response matrix rows, and quota/result tables.

name (TEXT, NOT NULL): Well label (for example gwm-well-N) imported from DECVAR/MPS and used for display and fallback matching.

trader_id (INTEGER, FOREIGN KEY to traders.trader_id): Assigned owner/trader for the well, populated by trader-well import. One trader can own more than one well.

gw_model_layer (INTEGER): Groundwater model layer index from DECVAR.

gw_model_row (INTEGER): Groundwater model row index from DECVAR.

gw_model_column (INTEGER): Groundwater model column index from DECVAR.

latitude (REAL): Well latitude imported from lat/lon file.

longitude (REAL): Well longitude imported from lat/lon file.

Table: control_points

control_point_id (TEXT, PRIMARY KEY): Control point identifier (for example gwm-cp-N), used across constraints and events.

name (TEXT, NOT NULL): Display name for control point.

gw_model_row (INTEGER): Groundwater model row index for control point.

gw_model_column (INTEGER): Groundwater model column index for control point.

latitude (REAL): Control point latitude.

longitude (REAL): Control point longitude.

Table: auctions

auction_id (INTEGER, PRIMARY KEY AUTOINCREMENT): Auction identifier used for all auction-scoped data.

status (TEXT, NOT NULL): Auction lifecycle state (for example OPEN/CLOSED).

created_date (TEXT, NOT NULL): Timestamp when auction row was created.

closed_date (TEXT): Scheduled close datetime (also used in page logic to infer closure).

firstWaterTakeDate (TEXT): First settlement/take period datetime anchor.

lastWaterTakeDate (TEXT): Last settlement/take period datetime anchor.

period_length_hours (INTEGER): Period size in hours for this auction context.

auction_type (TEXT): Auction category (for example tentative vs final).

solve_status (TEXT): LP solver status from latest run.

objective_value (REAL): Objective value from latest solved run.

Table: response_matrix

well_id (INTEGER, NOT NULL, FOREIGN KEY to wells.well_id): Source well for response coefficient.

control_point_id (TEXT, NOT NULL, FOREIGN KEY to control_points.control_point_id): Affected control point.

pumping_period (INTEGER, NOT NULL): Pumping period index in response matrix dimension.

effect_period (INTEGER, NOT NULL): Effect period index in response matrix dimension.

response (REAL, NOT NULL): Response factor coefficient linking pumping to control-point effect. A NULL value is treated as zero when read. The hydrologist may choose to omit rows with very small coefficients to keep the database compact; however, the rounding threshold must be chosen very carefully, because omitting small-but-numerous coefficients can systematically undercount the total hydrological effect at a control point and cause the market to accept more pumping than the aquifer can safely sustain. They hydrologist should also inspect response matrix coefficients (also called factors) that are positive, which implies injection rather than withdrawal. The Tianqiao data (tiansqiao.decvar) has only withdrawals, but the response matrix does have some positive values.

Primary key: (well_id, control_point_id, pumping_period, effect_period).

Table: response_matrix_info

Removed: This table was retired. Its settings were moved into Catchment_info key/value rows.

Table: well_license

license_id (INTEGER, PRIMARY KEY AUTOINCREMENT): License row identifier.

trader_id (INTEGER): Trader for this license row.

well_id (INTEGER): Well associated with this license row.

license_quantity (REAL): Licensed quantity value for the period.

license_date (TEXT): Optional source/license date-time for this row.

bid_period (INTEGER): Integer bid period index (for example 1..26).

Table: well_quota

quota_id (INTEGER, PRIMARY KEY AUTOINCREMENT): Trader quota event row identifier.

trader_id (INTEGER): Trader associated with this quota result.

auction_id (INTEGER): Auction that produced this quota row.

well_id (INTEGER): Well context for this quota row.

quota_auction_start (REAL): Initial/starting quantity prior to market adjustment.

quota_scaled_start (REAL): Quantity adjustment from clearing outcome.

quota_auction_end (REAL): Final quantity after adjustment.

price (REAL): Price associated with the row's auction-period settlement.

take_date (TEXT): Period/date key for the quota row.

Table: control_point_events

cpe_id (INTEGER, PRIMARY KEY AUTOINCREMENT): Control-point event row identifier.

control_point_id (TEXT): Control point associated with event/result row.

auction_id (INTEGER, FOREIGN KEY to auctions.auction_id): Auction scope.

effect_date (TEXT): Effect period/date key for the row.

actual_start_head (REAL): Base-run head h₀ at this control point and period (metres). Computed during MPS import as minimum_head minus LP_RHS, where LP_RHS is the GWM MPS RHS value (= hₗ minus h₀, e.g. −4.756 m). Corresponds to GWM Fortran variable HDCSTATE0. Only stored in the binary GWM response matrix file; not present in the MPS or GLOBAL output files; back-calculated here from the HEDCON BND and the MPS RHS.

minimum_head (REAL): Physical minimum allowed head hₗ at this control point and period (metres). Sourced from the HEDCON BND field (e.g. 829 m). Can be adjusted by the hydrologist per auction. The optimization LP constraint is: ∑(F × q) ≤ minimum_head − actual_start_head.

allowable_head_change (REAL): Allowed head change used in LP RHS form. During HEDCON import this column temporarily stages minimum head values (auction_id=0, effect_date='stg:{period}'). During MPS import it is rewritten as the final RHS value hₗ−h₀ for each real effect_date row.

Hydrologist maintenance rule: If you manually change actual_start_head for a control-point row, you must also recalculate and update allowable_head_change for that same row so the identity allowable_head_change = minimum_head − actual_start_head remains true. If this is not updated, optimization bounds and reported values will be inconsistent.

head_constraint_upper_bound (REAL): The LP bound value actually used in a completed solve run (= minimum_head − actual_start_head at solve time). Written by save_run_results; read by catchment_price_rows for post-run reporting.

range_lower (REAL): Reserved lower range statistic.

range_upper (REAL): Reserved upper range statistic.

slack (REAL): Constraint slack in solved run for control-point period.

dual_price (REAL): Constraint dual price for control-point period.

alpha (REAL): Alpha value copied for this event row.

GWM input data sources and how they map to control_point_events

The GWM2K Groundwater Management process for MODFLOW-2000 produces three input files relevant to control-point bounds:

  • HEDCON file (.hedcon): Defines head constraints. The BND field (token index 5) is the physical minimum head hₗ (e.g. 829 m for a GE-type constraint meaning head must be ≥ 829 m). import_hedcon stages this inside control_point_events.allowable_head_change using auction_id=0 and effect_date='stg:{period}'.
  • MPS file (.mps): LP problem in standard MPS format. The RHS section contains values equal to hₗ minus h₀ (e.g. 829 minus 833.756 = −4.756 m). The base head h₀ (GWM HDCSTATE0) is never written to the MPS file; it lives only in the binary GWM response matrix file (not distributed with Tianqiao data). import_mps reads staged minimum_head from control_point_events.allowable_head_change, computes actual_start_head = minimum_head minus LP_RHS, and writes final rows to control_point_events with allowable_head_change set to LP_RHS.
  • Response matrix file (binary): Written by GWM when IRM=1. Contains HDCSTATE0 per constraint. Not available in the Tianqiao data directory; actual_start_head is back-calculated from HEDCON and MPS as described above.

How the optimization uses these values: get_control_point_rhs computes the LP right-hand side as minimum_head minus actual_start_head for each control-point × period. This value drives the LP constraint: ∑(F × q) ≤ minimum_head − actual_start_head, where F is the response matrix coefficient. The hydrologist can adjust minimum_head per auction without changing actual_start_head.

Table: well_bids

bid_id (INTEGER, PRIMARY KEY AUTOINCREMENT): Bid row identifier.

well_id (INTEGER): Well where bid applies.

trader_id (INTEGER): Trader placing the bid.

auction_id (INTEGER): Auction where bid is submitted.

bid_date (TEXT): Bid submission timestamp.

effect_date (TEXT): Period key/date where bid quantity-price steps apply.

expiry_date (TEXT): Optional expiry timestamp/date for bid validity.

is_bid_default (INTEGER, default 0): Flag for system-generated/default bid handling.

qty1..qty5 (REAL): Up to five quantity breakpoints for stepwise bid curve.

price1..price5 (REAL): Up to five prices aligned with qty1..qty5.

deleted (INTEGER, NOT NULL, default 0): Soft-delete flag used to hide/cancel bids without hard delete.

Notes

SQLite type affinity is flexible; declared field types indicate intended use but SQLite may store compatible values across affinities.
