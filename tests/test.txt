Step 1. Create a release branch and stabilize
1. Create a branch (for example, release/public-v0.1).
2. Fix failing tests until pytest is green.
3. Freeze scope for first public release (no feature churn during polish).

Step 8. Publish and tag
1. Merge release branch.
2. Create annotated tag (for example v0.1.0).
3. Create GitHub Release with:
	- summary
	- install/run instructions
	- known limitations
	- link to docs pages/screenshots.

Step 10. website alignment (john.raffensperger.org)
1. Mirror the same license and limitation statements used in GitHub README.
2. Link website project page to tagged GitHub release, not only main branch.
3. Add a short reproducibility block on the website: Python version, install command, test command.

Step 11. What you still must do in GitHub UI (required for enforcement):
Go to Settings -> Branches -> Add rule for main.
Enable:
Require a pull request before merging
Require approvals
Require review from Code Owners
Require conversation resolution
Require status checks to pass
Disable force pushes and deletion
