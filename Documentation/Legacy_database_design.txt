NOTES ON QUOTA TERMINOLOGY

                       hydrologic constraints bind

     ControlPointMaxDrawdown):
         alpha = upper_bound / sum(F[well, CP, u, t] * quota[well, u, t])
     Alpha is capped at 1.0. If sum == 0, alpha = 1.0.
     Currently alpha is not computed or stored in ForeverFair2026.
     NEEDED: Implement alpha computation when bounds are applied or updated
     (see hydrologist/apply-default-bounds route). Store alpha in DB.
     [DONE April 2026 — _compute_alphas() in setup.py computes per (CP, period)
      using response_factors and trader_allocations; stored in
      control_point_bounds.alpha on apply_default_bounds(); copied to
      control_point_event.CPE_alpha when save_run_results() writes results.
      Alpha capped at 1.0; defaults to 1.0 if denominator is zero. Resolves F.7.]

D.3  Catchment model has constraint_periods field (int): the number of
     periods to apply hydrological constraints. Currently all periods in an
     auction are implicitly constrained.
     NEEDED: Decide whether to implement constraint_periods gating.
     [DONE April 2026 — Decision: constrain ALL effect periods present in the
      response matrix, not just the auction bid periods. If the response matrix
      covers 78 weeks and the auction has 4 bid periods, the LP enforces bounds
      for all 78 effect periods (lagged drawdown from bid-period pumping can
      bind constraints in later periods). Implementation: load() reads bounds
      from control_point_bounds (all periods imported via .mps or seed);
      runAuction() iterates control_point.bound_by_period.keys() for both
      constraint generation and constraint_results collection.
      Also fixed: load() now reads from response_factors and control_point_bounds
      (the tables that both seed and import_mps write to), replacing the stale
      reads from response_matrix and control_point_event.]

D.4  ConstraintQuota is pre-computed on Auction post_save:
     one row per (well, control_point, period, auction), storing alpha and
     the computed proportional constraint value.
     Currently ForeverFair2026 has no ConstraintQuota equivalent.
     NEEDED: Implement ConstraintQuota computation during auction setup or
     solve. This table is the basis for proportionalAllowance logic.
     [DONE April 2026 — constraint_quota table added to schema
      (auction_id, well_id, control_point_id, period_id, alpha, quota_value,
      constraint_quota_value). _compute_constraint_quotas() in setup.py
      computes cq(well, CP, t) = alpha(CP, t) * quota(well, t) for every
